# ANDROID_GRADLE_JVM_ARGS

Update `org.gradle.jvmargs` in `android/gradle.properties` when it still has
the value an older `flutter create` generated.

Recommended step: planned with `--include ANDROID_GRADLE_JVM_ARGS` or
`--include-recommended`.

## What it detects

`org.gradle.jvmargs` equals (ignoring whitespace) the value generated by the
app template of an earlier Flutter release, and differs from the value
generated by the target release.

Values that match no template are customized and never changed. A value
generated by a release newer than the target is never downgraded.

## Why

Flutter changed the Gradle JVM settings of its template several times:

| Flutter | `org.gradle.jvmargs` | Change |
| --- | --- | --- |
| 3.0.0 to 3.13.9 | `-Xmx1536M` | |
| 3.16.0 | `-Xmx4G` | [flutter/flutter#133671](https://github.com/flutter/flutter/pull/133671) |
| 3.22.0 | `-Xmx4G -XX:+HeapDumpOnOutOfMemoryError` | [flutter/flutter#143085](https://github.com/flutter/flutter/pull/143085) |
| 3.24.0 | `-Xmx4G -XX:MaxMetaspaceSize=2G -XX:+HeapDumpOnOutOfMemoryError` | [flutter/flutter#146275](https://github.com/flutter/flutter/pull/146275) |
| 3.29.0 | `-Xmx8G -XX:MaxMetaspaceSize=4G -XX:ReservedCodeCacheSize=512m -XX:+HeapDumpOnOutOfMemoryError` | [flutter/flutter#156201](https://github.com/flutter/flutter/pull/156201) |

The values are generated into the knowledge base from
`templates/app_shared/android.tmpl/gradle.properties.tmpl` (before 3.29) and
`templates/app/android.tmpl/gradle.properties.tmpl` at every release tag.

Setting any JVM argument replaces all of Gradle's default JVM arguments, so a
bare `-Xmx` leaves Metaspace unbounded; this is why later templates set
`MaxMetaspaceSize` too (see flutter/flutter#143085).

Observed by Reforge: a Flutter 3.3 app migrated to Flutter 3.47 with the
3.3-era `-Xmx1536M` failed `flutter build apk --debug` with `Java heap space`
in a Jetifier transform, and built with the 3.29+ value. `reforge verify`
explains such failures as `GRADLE_OUT_OF_MEMORY`.

## What it changes

The value of `org.gradle.jvmargs` is replaced with the target template's
value. The key, separator, comments and every other line are kept.

## Status

| Status | When |
| --- | --- |
| auto | The value is an unmodified template value. |

The note on the step shows how the maximum heap changes (for example
`1536M` to `8G`). `-Xmx` is a limit, not a reservation, but machines with less
memory than the limit, such as small CI runners, may need a lower value.

## Verification

Static checks and `flutter build apk --debug`.
